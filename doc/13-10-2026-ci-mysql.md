## 1. Bỏ chạy trùng

Trước đây CI chạy khi push lên **mọi** nhánh và khi có PR vào `main`, nên một commit trên nhánh
đang mở PR bị kiểm tra hai lần. Giờ CI chạy khi:

- tạo hoặc cập nhật PR vào `main`
- code vào `main`
- bấm **Run workflow** ở tab Actions (chọn nhánh bất kỳ)

Hệ quả: push lên một nhánh **chưa mở PR** thì CI không tự chạy nữa. Muốn kiểm tra sớm thì mở PR
(có thể để Draft) hoặc bấm Run workflow.

## 2. Test chạy trên MySQL trong CI

Trước đây CI dựng MySQL và nạp `database/init/01_schema.sql` nhưng test lại dùng SQLite, nên file
SQL không được kiểm tra. Giờ job backend đặt `TEST_DATABASE_URL` trỏ vào MySQL đó:

- Bảng do `01_schema.sql` tạo ra, test **không** tự tạo bảng trên MySQL. Nếu file SQL lệch với
  model (thiếu cột, sai tên) thì test sẽ đỏ.
- Sau mỗi test, dữ liệu trong các bảng bị xoá để test sau bắt đầu với DB trống.
- Ở máy cá nhân không đặt biến này thì vẫn chạy bằng SQLite như cũ.

## 3. Bỏ `|| [ $? -eq 5 ]`

Đoạn này cho CI qua khi chưa có test nào. Giờ đã có test nên bỏ; nếu lỡ không thu được test nào
thì CI sẽ báo đỏ thay vì im lặng.

## Kiểm tra

Chạy trên máy với Python 3.12:

- `ruff check .`: không lỗi
- `pytest` với SQLite: 15/15 qua
- `pytest` với MySQL 8.0 thật (container Docker, nạp `01_schema.sql` giống CI): 15/15 qua,
  bảng `alerts` trống sau khi chạy xong

Phần điều kiện kích hoạt của workflow chỉ kiểm tra được trên GitHub, sau khi mở PR cho nhánh này.

## Cách chạy test với MySQL ở máy

```bash
docker run -d --rm --name cws-test -p 3307:3306 \
  -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=collision_warning_test \
  -e MYSQL_USER=cws_user -e MYSQL_PASSWORD=cws_password mysql:8.0
docker exec -i cws-test mysql -uroot -proot collision_warning_test < database/init/01_schema.sql
cd BE
TEST_DATABASE_URL="mysql+pymysql://cws_user:cws_password@127.0.0.1:3307/collision_warning_test" pytest
docker stop cws-test
```
